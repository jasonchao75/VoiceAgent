# Add Call History and Metrics

## Why

当前录音、对话文本和服务端延迟事件只存在于实时会话或日志中，会话结束后无法回看，既不利于产品验收和故障定位，也无法为后续 ASR Benchmark 积累可筛选的真实语料。

## What Changes

- 建立持久化通话记录，保存会话摘要、逐轮 ASR/LLM 文本、错误诊断和服务端/浏览器延迟指标。
- 默认保存用户上行音频，不保存机器人 TTS 下行音频；音频使用适合后续 ASR Benchmark 的无损格式。
- 新增历史通话列表、详情、录音播放/下载和手动删除能力。
- 文本与指标默认保留 30 天，录音默认保留 7 天。
- 增加磁盘容量保护：录音有效配额不超过 5GB 或数据卷总容量的 20%（取较小值），并保留最低安全剩余空间。
- 对记录的 LLM/TTS 首包延迟区分服务端厂商链路和浏览器播放链路。
- 按轮保存 LLM reasoning token 数量、关闭策略和验证状态，用于解释异常首 Token 延迟；不保存隐藏思维链正文。

## Out of Scope

- 不建立正式训练集或自动把线上通话加入 ASR Benchmark。
- 不保存 TTS 下行音频、多轨混音或屏幕操作录像。
- 不提供多租户权限体系；历史记录与 Bot 一样，在 Basic Auth 保护后的实例内共享。
- 不做无限期归档、对象存储、全文搜索和复杂 BI 看板。
- 不声称能排除服务器到 LLM/TTS 厂商之间的公网耗时；只能将浏览器网络/播放耗时与服务端观测耗时拆开。

## Success Criteria

- 用户可按时间查看历史通话，并打开详情查看逐轮文本、录音、错误和延迟。
- 文本/指标保存 30 天；录音保存 7 天，过期或超额后先删除最旧录音而保留文本。
- 磁盘不足或录音写入失败不会中断实时通话，记录明确标记录音不可用原因。
- 保存的用户音频可关联采样率、格式、语言、ASR provider/model、Bot 和 Transcript，为后续人工筛选 Benchmark 提供基础。
- API Key、Prompt 中的秘密和 Authorization 数据不进入历史记录。
- 清理任务可重复执行，应用重启后仍按保留期与容量规则工作。

## Dependencies and Delivery

- 依赖 `improve-llm-diagnostics` 的错误类别和 `diagnostic_id`。
- 两个 Change 实现、测试和验收后合并为同一版本部署。
- 部署前需只读确认服务器数据卷容量与剩余空间；若默认 5GB 不安全，应降低 `VOICE_AGENT_RECORDING_MAX_BYTES`。
