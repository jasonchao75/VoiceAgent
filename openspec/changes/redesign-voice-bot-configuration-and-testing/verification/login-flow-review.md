# 登录改版最终产品确认页

Status: **产品行为已于 2026-09-10 确认；登录页原型待视觉确认，尚未实现。**

## 为什么会重复弹窗

目前网站登录和一次 Chat/Web call 都挤在同一个 HTTP `Authorization` 位置。通话指标请求带上自己的临时 Token 后，服务器误以为网站没有登录，于是再次触发浏览器自带登录框。

独立登录页只有在同时改成安全 Cookie 登录时才能解决根因。之后：Cookie 负责“是否已进入网站”，临时 Token 只负责“是否能读取这一次通话”，两者互不覆盖。

## 你只需要确认三项待定内容

| 产品判断 | 推荐方案 | 用户体验 | 状态 |
|---|---|---|---|
| 账号范围 | 继续使用现在的一个共享账号 | 本期不做注册、多用户、角色和找回密码 | 已确认 |
| 登录有效期 | 连续 12 小时无操作才过期；活跃使用自动续期；提前 5 分钟提示；最长连续登录 7 天 | 正在操作时不会突然退出，长期无人使用也不会永久保持登录 | 已确认 |
| 登录后的去向 | 回到登录前准备访问的站内页面 | 例如从 Sessions 过期，重新登录后仍回 Sessions；尽量保留未提交表单 | 已确认 |

## 已确认，不需要重复审核

| 内容 | 已确认行为 |
|---|---|
| 退出入口 | 左侧栏底部显示用户头像；桌面端 hover/focus、触屏端点击头像后显示 `Log out` |
| 退出结果 | 点击后立即结束当前浏览器登录并返回登录页 |
| 原生弹窗 | 登录、过期和通话指标请求均不得再触发浏览器自带登录弹窗 |
| 技术分工 | 网站登录使用安全 Cookie；单次 Chat/Web call 继续使用独立临时 Token，两者互不覆盖 |
| 品牌名称 | 全站统一为 `VoiceAgent Demo`，不再出现 `Flux Agent Platform` 或 `Flux Voice Lab` |
| 登录视觉 | 与现有平台深色、绿色强调和组件语言一致，保持设计感，不采用通用后台模板 |

## 你不需要审核的技术细节

- Cookie 如何签名、密钥如何保存、接口怎样区分网站登录与通话 Token。
- 防暴力尝试、通用错误文案、自动化测试和不再出现原生弹窗的回归检查。
- 登录页的像素和窄屏适配首轮排查；这些由 Agent 根据确认后的原型完成并提供证据。

## 确认后的交付顺序

1. 先补登录页原型和四个关键状态，由产品只确认页面方向。
2. 再实现登录、退出、过期跳转和鉴权分离。
3. 自动测试登录全流程及 Chat metrics，固定视口截图对比后再请产品最终验收。

## 如何确认

行为方案已经确认。下一步只需查看 `prototypes/login.html` 的视觉方向；确认后 Agent 才进入鉴权实现。当前重复弹窗会加入回归测试，确保登录后完成 Chat test、读取逐 Turn metrics 全程不再出现浏览器登录框。
