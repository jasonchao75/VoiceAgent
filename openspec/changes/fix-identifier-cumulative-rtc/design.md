# Design
Ledger区分本地收集来源与真正LLM提交范围。只有完整来源、未提交范围可以随该来源更新；编号collection复用source-bound替换、generation隔离。提交LLM后冻结范围，禁止扩大旧普通话轮。
RTC统一选择函数用于session响应、transport安装、input时钟和pipeline协议；启用自建TD且优先编号规则的会话走既有RTP任务播放，其他默认保持native。音频仍RTP/Opus，不走数据通道PCM。客户端能力不足按既有明确失败处理，不伪报跟读。

连接前mobile_call_error通过现有Bearer events接口认证pending lease并原子移除；active仍沿用原链路，原子锁确保与claim互斥。失败历史录入not_started，前端等待上报最多3秒，finally清理。兼容性仅能力探测与明确错误，不用UA猜测，不静默native降级。

浏览器适配：优先RTCRtpScriptTransform；缺失时若receiver.createEncodedStreams可用，将readable/writable传给同一个worker复用现有处理函数。before SDP阶段绑定，不改SDK、不覆写全局RTCPeerConnection、不改RTP传输。AudioDecoder仍必需，缺能力明确失败并释放资源；没有完整手机矩阵不能宣称全浏览器兼容。

连接误断修复：按可靠控制通道的来源顺序匹配RTP包，只有完整范围由task=null覆盖的服务端静音可跳过。跳过不产生PCM或播放成功事实，保留缺包证据；任务音频缺失仍失败。连接错误首次胜出，后续SDK清理错误不覆盖原因。

控制就绪采用连接自身datachannel open事件；MappedRawAudioTrack首个recv前等待，沿用SDK DATA_CHANNEL_TIMEOUT_SECS=10。超时从独立受控任务disconnect，避免sender关闭等待自身；首帧时钟重新锚定，连接等待不计入音频。对已认证mobile_call_error的RTC会话显式取消；offer注册与撤销共用锁并再次验证active lease。无capture时补终态历史，不覆盖已有服务端错误类别。

扫码RTC新端点沿用既有通话Bearer鉴权边界：精确匹配playback-events、playback-clock、playback-clock/{sample_id}、rtp-input，仅绕过网站Cookie层；路由内session token/任务/时钟校验全部保留。测试必须开启网站认证并清除扫码浏览器登录Cookie。

匹配超时修复先区分等待证据与等待解码：mapping_deadline只用于确实缺少映射的包；映射已齐备但等待有序解码的包不得被误报为缺映射。保留单次解码1000ms上限、映射/音频队列100条上限、缺任务音频拒绝和散列身份校验，不增加现有等待阈值。生产两次事件尚不足以唯一确认内部状态；仅根据可复现测试修复，保留真机未验证范围。

静音缺包到期只标记可退休并驱动有序drain，不能在非队首直接报任务缺包，也不能跨越正在解码的前序修改来源游标。关闭采样器为不可逆终态；RTC关闭前先阻断迟到控制消息。首错诊断只允许固定构建标识、计数、队首/目标包是否存在及来源范围类型，不记录音频、文本、地址或token。

接收与解码分离：RTP transform仅复制到100条有界队列并触发有序drain，不await解码；保留现有身份/截止/真实回执。原生getStats每500ms采样，最多一个在途请求，首错同步读取缓存，仅上报received/lost/discarded数值及从请求开始计的年龄，关闭不等请求且拒绝迟到更新；closed播放器不得重新创建peer。worker记录已完成解码最大耗时和接收间隔，不用这些统计伪证具体包归因。

播放器模块发worker_ready，客户端在原RTC连接前以10秒有界等待确认模块可执行；监听error/messageerror并锁存ready后、bridge建立前的失败。该握手不代表解码或可听成功；运行时仍走原bridge失败清理。公开demo页面和直接demo.html返回no-store；无法追溯修复已打开旧页，缺失旧hash资源时提示刷新，不切到原生无身份播放。
自建TD使用标准RTVIProcessor工厂的专用observer，仅忽略TDSubmissionFrame；保留厂商Interim/Final事件、其他RTVI、普通模式原observer和LLM链路。手机现有UI仅显示厂商Final，不将内部Partial提交伪作厂商Final；来源可修订Partial字幕不在此修复范围。

## Approved repair 2026-10-28 (supersedes task-renderer design above)
正式RTC自建TD含编号规则走native RTP/Opus。服务端串行输出使用原生track消费future进行20ms有界发送，不以SDK排队等同发送完成；取消中断当前writer并清理原生track待发队列。队列按服务端发送终态释放，无客户端回执、包映射或WebCodecs依赖。客户端实际开播/结束保持未知。输入、录音和ASR音频时钟沿用native链路。
编号计划以同来源规范化单元序列区分格式、追加与真实更正；跟踪已开始发送的单元位置，追加保留旧未发尾段，真正更正撤销旧未发范围并补读完整最新来源。不同来源相同数字不去重。回调检查collection generation及来源版本。
Final比较仅去Unicode标点和空白；一致更新转写与上下文但不重新发LLM，不改变response ID和副作用归属；不一致沿用受控取消重答。旧轮次Final仍拒绝。
