# 利雅得银行分行转接质检上下文 v1

## 业务目标

根据用户提供的分行信息、客户类别和服务诉求，把用户转接到正确的人工部门。质检只判断历史用户转写是否可能改变业务含义，不评价机器人话术是否优秀，也不把评测 ASR 当作 Ground Truth。

## 标准流程

语言选择 → 获取分行名称或三位分行代码 → 必要的澄清与确认 → 获取客户类别或服务诉求 → 确认转接。

## 重点实体与术语

- 语种：阿拉伯语、英语、阿英混合。
- 分行信息：城市、分行名称、道路或区域、三位分行代码。
- 客户类别：Golden、Diamond 及其阿拉伯语表达。
- 服务诉求：查询、开户、补卡、经理诉求、转接部门等。
- 逻辑词：肯定、否定、纠正、改口和转接确认。
- 分行名称与代码来自该上下文所关联的参考词典实例 `riyadbank_branches`；运行时由系统随批次冻结后统一放入 `{{reference_dictionaries}}`。

## 判断规则

1. 只把用户事件作为质检目标；机器人事件仅用于理解上下文。
2. 用户只提供城市时，机器人追问具体分行属于正常流程。
3. 用户可能主动改口；信息变化本身不能证明前一句转写错误。
4. 机器人重复询问可能来自用户未回答、回答不完整、TTS 被打断或端点检测异常，不一定是 ASR 错误。
5. 最后一句用户回答不能反向作为前面事件的标准答案。
6. 阿拉伯语字形、标点、大小写、空格、填充词和不改变业务含义的口语差异不作为错误。
7. 分行、城市、三位代码、客户类别、服务诉求、语种和肯否关系发生变化时，必须保留可定位证据。
8. 不能根据模型自身知识补充分行名称与代码映射；参考词典只能辅助发现疑点，不能证明用户实际说了什么。

## 已知风险

- 阿英混说可能造成语言判断或切句错误。
- 用户与机器人重叠发言可能造成说话人混入。
- 三位数字容易被截断、拆分、合并或格式化。
- 阿拉伯语分行名称、城市和道路名称容易被近音词替换。
- Golden、Diamond 等客户类别可能被识别为相近普通词。
- 肯定、否定和自我纠正可能改变转接含义。
- 完整通话录音的声道不一定等于用户/机器人角色，必须结合 speaker、时间和上下文判断。

## 输出边界

- 第一轮只提出可回听疑点，不能声称听过录音或生成标准答案。
- 第二轮把历史转写和各家评测 ASR 都视为证据，不使用多数票或 confidence 阈值代替证据判断。
- 听不清、说话人归属不清或证据无法形成非空标注时进入人工复核。
