# 附录：研发实现细则

本文说明HOW，不另立一套行为标准。WHAT以[voice-pipeline Delta](../specs/voice-pipeline/spec.md)、[bot-config Delta](../specs/bot-config/spec.md)和最新有效决定为准；执行勾选仅在[当前tasks](../tasks.md)。

## A．嵌入现有工程

| 当前入口 | 研发要做什么 | 主要回归风险 |
|---|---|---|
| `src/asr/config.py`、`factory.py`及Catalog | 增加self_developed能力，补原事件/Partial桥接与公共视图 | 只改下拉框却未接运行时；错误关闭厂商协议收口 |
| `src/bots/`、`src/session.py` | TD/Jev/编号配置与凭证归属、不可变会话快照 | 新配置漏持久化、跨Bot/会话泄漏、明文凭证回显 |
| `src/pipeline/voice_agent.py`及锁定聚合器 | 显式自建策略、唯一提交、异步TD任务与工具、输出仲裁 | 框架默认/服务metadata恢复旧策略、超时旁路提交 |
| `src/pipeline/assistant_context.py` | 普通回复上下文和关键词快照版本 | 跟读覆盖普通提示、流式块被误算成多轮 |
| `src/history/`、`src/observability*` | 拆分来源Final、TD提交、工具、回答版本、播放回执 | Partial伪装Final、重答/跟读污染普通延迟 |
| `frontend/src/`及现有正式路由 | 设置联动、Jev页、词表音频、逐轮证据 | 另造静态壳、刷新丢状态、浮层横向滚动 |

以上是已存在模块入口，不预设必须新增哪些类或生产依赖。按锁定Pipecat 1.8.1和Speechmatics Voice SDK 0.2.8核查；不要套用不同协议代际或未锁定文档。细节见[ASR映射](asr-event-mapping.md)。

## B．先定义会话内的状态边界

| 边界/标识 | 解决什么问题 | 必须隔离的情况 |
|---|---|---|
| session、stream_epoch | 会话与ASR连接身份 | 重连后时间和序号复用 |
| source_range、source_revision | 相同音频的文字覆盖和修订 | Partial快照重复追加、旧Final清掉新尾部 |
| turn、candidate、speech_generation | 用户轮次和其中多个停顿尝试 | 续说后旧Jev/定时器仍提交 |
| committed_range及提交快照 | 已交给LLM哪些音频/文字 | 厂商同一个turn跨越自建提交，旧前缀重复收集 |
| collection_generation | 编号收集代次 | 清空/新采集后旧工具、跟读、补合成回写 |
| response_revision、playback_task | 同轮重答和每段输出身份 | D-043重答后旧token/音频流入新回答 |

字段可沿用项目已有命名；不能只用字符串内容替代音频位置。缺少可靠范围时保留未知证据、先核查适配；不能猜测并将未知标为通过。ASR稳定前缀并不自动意味着整个TD候选Final。

## C．TD时序与并发

1. 音频持续进入原ASR与Silero；本地VAD输入路径不能因Jev、磁盘或合成阻塞。
2. 按有效来源范围维护当前完整转写，候选停顿时决定纯编号/混合/普通路径；混合请求不被未满位保护卡住。
3. 所有异步结果绑定候选/转写/上下文配置版本。续说及实质修订使旧结果失效；取消请求只是节约资源，结果回调仍须版本校验。
4. 普通路径最长看门狗独立于Jev；目标等待减已耗静音一次，Final窗口取自身到期与最长截止较早者。
5. 提交前最后检查有效候选、非空文字、当前语音状态与未提交状态；序列化提交与取消竞争，不能靠两个异步任务分别判断后都提交。
6. 正常静音、疑似开口、断流/输入积压分别记录。临界续说保护不得暗中引入无界等待；具体边界给可控时间测试证据，若现有Spec不能唯一决定体验，按项目流程提出具体冲突。

Jev超时、非法数值、缺分类、文字变更、限流/鉴权失败均测试。容差、重试/节流、熔断与默认等待先给可验证建议；需要改变成本或可观察体验时确认，不将原型示例直接上线。

## D．编号路径与工具

- 纯编号严格全输入格式校验：词表别名、规范化、明确格式分隔符；不加固定最小片段位数。普通前缀/语气词/提问/更正走完整LLM路径，不能在工具之前偷偷抽数字。
- 提交工具的工程最小输入须能关联当前会话、有效来源范围/版本/代次及编号内容；实际字段名在实现设计确定。系统核对内容来自有效转写和词表，重复操作幂等，返回真实编号与位数/错误。
- 清空工具校验当前代次并原子清空值/计数、失效旧任务；成功才口头确认。主动更正均完整重念，自动ASR修订按原范围替换而非追加。
- 两条路径使用相同状态层；同一内容若先被本地处理，不能随后通过工具再加一次。Partial由纯编号变混合句，重新分流与撤销未生效工作，保留已发生事实。
- WPM使用有效编号范围真实首尾时间和业务单元数；缺时间不猜。混合句工具提交成功不意味着可以用整句时间声称WPM达标。
- 目标位数不是片段门槛。未满独立保护；刚满交语义TD；超位短停顿提醒。成功标志和下一次采集事件要可追溯，不能因每包或关键词重复出现清空。

详见[更正注意事项](corrections-and-cautions.md)。对话LLM工具支持与失败分类必须测试，拒绝工具调用的模型不能静默用普通文字执行控制。

## E．D-049：Final替换已提交Partial

同一范围的Partial已提交且对应回答仍属当前轮次时，首个有效Final到达后立即取消对应旧生成和播放，更新有效上下文并以Final重新请求。不判断是否实质改义，相同文字、标点变化和同义表达也适用；不调用额外语义比较API。

重复或格式化重发Final不再次重答；新轮次已经开口后旧Final不得中断新轮次。原用户提交只计一次，回答版本单独记录。历史保留原Partial、Final、已播事实、取消原因及新回答身份。

重答不能无条件重放已执行的提交/清空等工具。按原用户轮次与来源范围核查成功操作，旧代次工具不得清空新状态。取消必须实际传播至生成、队列、传输和客户端；仅换一个状态字段不能证明残留音频已停止。

## F．播放、缓存和历史

播放必须用[用户实际选择](../decisions/playback-decisions.md)，不是推荐列：P03=B；P04上一段始终优先；P05清空停止旧跟读；P06旧补合成失效；P07普通打断清旧待播；P08一次持续沉默只提醒一次；P10未播修订合并；P11客户端开播证据及在途未知状态。

已入队、已发送、客户端确认已播不可混为一谈。缺回执不证明未播放；取消后需要阻止旧队列/传输/客户端缓冲继续污染下一输出。普通续说不取消有效在播跟读，但明确清空是已确认特例。

缓存指纹、发布绑定、格式拼接、固定语速、永久保存及临时补合成见[缓存细则](echo-audio-cache.md)。合成任务有界、日志不含密钥；不为Publish自动产生费用。

历史事件至少关联turn/candidate/source revision/response revision/playback id，区分Jev、TD提交、ASR Final、工具与首播。Partial先提交时Final指标可缺失；不得改造事实来迁就旧报表。浏览器AEC必须查音轨实际设置并实机测试双讲，文件混音不能证明物理回声被消除。

## G．验收材料怎么组织

[自测计划](../verification/self-test-plan.md)定义场景；[自测报告](../verification/self-test-report.md)只填实跑结果。证据放verification下按阶段组织且链接可定位；不保存明文密钥或未经授权客户录音。开发者自测后交[独立审核流程](../handoff.md)，审核人检查实现与证据，不仅批准文档结构。
