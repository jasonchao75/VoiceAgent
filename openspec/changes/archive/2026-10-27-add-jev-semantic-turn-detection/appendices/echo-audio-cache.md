# 数字 / 字母跟读音频预合成与持久缓存（设计草案）

## 产品行为

**配置期生成并试听，Publish 校验完整性，通话时直接读取音频。** 本文仅描述本次新增设计，不表示已存在真实合成、存储和播放功能。

| 时机 | 行为 |
|---|---|
| 编辑词表 | 按规范化后的“跟读目标值”生成待合成单元清单；相同目标单元只保留一份，不按识别词重复生成 |
| 点击词表标题旁“一键合成” | 正式实现中由后端读取当前 Bot 的 TTS 配置和服务端凭证，合成缺失 / 不匹配的单元；返回逐项状态和试听资源 |
| 合成完成 | 在每行单项试听；失败项明确标失败，可针对失败项重试，不能假装整批成功 |
| 保存 | 音频作为服务器持久资源永久保存，不随页面关闭、会话结束或服务重启自动清理；前端仅负责展示和试听，不依赖浏览器内存 / localStorage 作为唯一存储 |
| 每次 Publish | 检查当前词表所需单元、当前有效 TTS 配置与可读音频资源是否一一匹配。缺失、失败或过期不匹配时阻止发布，提示先手动合成；Publish 不自动产生 TTS 调用 |
| 通话跟读 | 取相应发布版本的单元音频，按顺序拼接，通过现有音频输出链路播放；正常缓存命中路径不调用实时TTS；运行时缓存读取失败则临时合成并留痕 |

用户已确认“每次 Publish 检查、永久保存、前端提示、缺失阻止发布”。真实付费合成仍须按项目规则记录本次调用的数据范围、厂商、费用上限和停止条件；原型按钮不发真实请求。

## 词表与音频关系

- 示例 `one → 1`、`一 → 1` 只需一份“1”的目标音频，不合成两份识别词音频。
- 数字 / 逐字母编号以规范化后的独立单元作为资源；多位数字目标 `123` 对应 `1`、`2`、`3`，不依赖整串实时合成。其他目标值以词表定义的单元为准，不盲目拆普通单词。
- 跟读内容不改变编号计数口径：英文词、中文汉字和数字逐位的既定规则保持不变。
- 单独合成数字的读法取决于 TTS 语言、声音和模型；单元试听与实际连续播报都要验收，不能仅凭文件存在宣称读法正确。
- 缓存只覆盖词表有效输出范围；用户输入未在有效词表内的内容不得当作已缓存数字播放。

## 缓存匹配与失效

缓存记录至少关联 Bot、跟读单元 / 实际合成文本、TTS 厂商、实际模型 / 版本（可确定时）、voice id、语言 / 发音设置、有效语速及其他影响音频的设置、采样率 / 声道 / 编码、资源版本、生成状态、完整性信息。

- 以影响发音的有效配置计算匹配指纹；凭证不下发、不写入可见缓存元数据，不将明文密钥纳入日志。
- 新增词表目标单元，只补缺少的音频；已有匹配资源可复用。
- 改声音、模型、语言、合成语速或其他影响音频的参数时，旧资源仍永久保存，但标记为与新配置不匹配；不得借用旧音色通过 Publish 校验。
- 只改“数字间播报空隙”，不重新合成，因为它是播放拼接参数。
- 发布时绑定已校验的资源清单和版本；校验与发布期间配置变化需重新校验，不能用上一份校验放行新配置。
- 通话内调语速只影响普通回复；数字跟读保持发布时语速。缓存缺失时的临时补合成也使用该发布版本的跟读配置，不随普通回复动态语速变化。

## 播报空隙与音频拼接

新增“数字 / 字母间播报空隙”，建议默认 **50 ms**，支持非负整数毫秒调整；默认值来自本次用户建议，仍需听感验证。

例如 `1 → 50 ms 静音 → 2 → 50 ms 静音 → 3`：仅相邻单元之间插入空隙，不在末尾额外追加。相同数字连续出现时保留真实次数，例如 `11` 播放两次“1”，中间仍插入一次空隙。

服务端将素材统一为与现有输出链路兼容的音频格式后拼接；不能直接拼 MP3 文件头或把不同采样率字节流混接。空隙按音频采样数生成并加入连续播放队列，不依靠阻塞 sleep 实现。素材可能自带头尾静音，50 ms 是额外插入值，实际听感间隔需连同素材检验；不默认激进裁切，以免截掉轻音和尾音。

常用单元可在发布 / 会话准备阶段预读（仅读取已存在资源，不触发合成），避免命中后才启动外部合成。当前方案旨在去掉运行时合成等待，不能在未实测前承诺具体首播延迟。

## 页面原型（v0.12，取代分离清单）

词表行本身承载全部信息：识别词列表（半角或全角逗号分隔）→ 跟读文本 → 音频状态与试听 → 删除。多个别名共用一个目标音频。表头旁放“一键合成”，批量处理缺失或失配目标；不再单独重复展示缓存清单或整串试听。间隔在词表下面独立设置，默认建议50ms。

前端用简短文案提示当前TTS、永久保存和Publish校验。无真实音频时行内试听禁用；一键合成在原型中只校验词表，不调用付费API或伪造成功。行内及跨行重复别名被识别为冲突，空别名 / 空目标不通过校验。

## 运行时缓存失败（已确认）

发布前仍必须校验并阻止缺失；发布后读取失败时，使用发布版本TTS跟读配置临时合成，再播放跟读。按既定持久缓存规则保存匹配资源，并对并发请求去重。会话逐Turn记录缓存读取失败、涉及单元/配置版本、临时合成路径、结果和耗时；不能显示为普通缓存命中，不记录明文凭证。

临时合成使用有超时的异步调用；具体重试预算和超时值由工程设计，不能无界重试。若临时合成本身失败，按现有TTS错误链路可诊断失败，不伪造成功。此次确认是产品运行规则，不代表授权Agent本轮执行真实付费测试。

## 待实施验收

- 多个识别词映射相同数字只生成一份目标音频；重复数字在播报序列中不被去重。
- 冷启动 / 浏览器刷新 / 新会话仍能使用已持久保存的音频；旧资源不会因新配置发布而自动删除。
- 单项合成失败明确显示，其他成功项不重合成；缺失项使 Publish 不通过。
- 改声音或语速使当前资源不匹配，不能拿旧缓存发布；改间隔不触发 TTS 调用。
- 空隙 0 / 50 / 自定义毫秒可听辨，整体输出无采样率错配、重复帧、异常爆音；端到端时序另外测量。
- 正常跟读只读缓存；不新增第二次 LLM 回复，也不改变原有跟读去重和用户可同时说话的规则。
- 运行时读取失败触发临时TTS补合成并在会话留痕，验证跟读仍保持发布语速；发布校验不等于存储永远不会故障。

## 未验证范围

尚未调用任何 TTS、生成或存储真实音频。未验证各声音独立数字发音、拼接连贯性、素材静音、首播延迟、永久存储备份及临时合成故障处理。现有 ASR / 编号状态未完成事项仍有效。
