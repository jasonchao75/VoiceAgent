# 更正与注意事项：严格本地规则＋LLM工具

状态：用户已确认设计调整；仅更新需求与自测要求，功能尚未实现。

## 1．两条处理路径

| 用户输入 | 谁理解 | 谁修改编号 |
|---|---|---|
| 纯编号，例如12345，整体符合词表与编号格式 | 本地规则，不额外请求对话LLM | 本地调用统一编号状态逻辑；满足既有低速、可靠时间、停顿等条件才跟读 |
| 正常混合表达，例如“我的号码是123” | Jev决定何时交出话轮，现有对话LLM理解内容 | LLM调用受控提交编号工具；校验成功后更新同一份编号状态 |
| 更正表达，例如“不是123，是124”“把第4位改成3” | 同上，不由本地正则理解更正意图 | LLM调用清空编号工具；成功后提示完整重念，不局部替换、不直接采用124 |
| 普通询问，例如“现在几位了”“one moment” | 普通语义TD及对话LLM | 无有效编号提交或清空意图时，不修改编号 |

**本地规则严格，指整体格式校验严格，不是增加一堆否定/更正正则。LLM工具是混合表达的正式处理路径，不是仅在本地出错后才补救。**

本决定替代此前“允许前缀，直接从整句抽取数字”的设计。正则/词表只承担编号格式、合法单元和明确分隔符检查；不因一句话含数字子串就收集，不新增固定最低位数。关键词场景门槛继续保留，混合工具不得绕过有效采集上下文。

## 2．“不是123，是124”完整流程

1. 当前输入含普通表达，不满足纯编号格式，不能先将123或124加入编号或排队跟读。
2. 整句进入Jev普通语义TD；保留既有最短/最长/Final等待和续说撤销规则，不新增独立理解服务。
3. 现有对话LLM识别更正，调用清空编号工具。
4. Pipeline清空当前编号、复位计数、切换采集代次，使旧待播与在途写入任务失效；按用户已填P05停止旧跟读。
5. 工具返回成功后，才回复“好的，请重新念完整编号”；失败不能声称已清空，也不能自行把124当作新编号。

“我的号码是123”则走提交工具：LLM提供待提交编号，由系统核对来源、词表、版本与去重后写入，返回更新后的编号/位数。文字回答“已记下123”本身不代表状态已更新。纯编号不需要额外调用该LLM工具。

## 3．实现注意事项

- **按当前输入范围判断，不按每包ASR单独判断。** Partial可能先像纯编号、随后变成混合表达；重新分流时撤销失效待收集/待播任务。已经听到的音频不能撤回，不能承诺预知未来语音。
- **本地与工具共用一份状态。** 两条路径都带会话、音频来源范围、修订版本和采集代次；相同输入重复包/重复工具调用不重复计数，不同位置真重复的数字仍保留。
- **工具不能任意写数字。** 系统校验参数对应当前有效转写与词表；过期调用、无依据数字或非法参数拒绝处理。清空操作也不能清到新的采集代次。
- **意图与ASR修订分开。** 用户主动更正按清空处理；同段ASR自动改字仍按既有修订/补读规则。同一范围多个未播修订合并为最新有效版本（P10）。
- **输入边界决定路由。** 同一句“123，接下来还要几位”现在按混合路径，不先本地抽取。若123此前已独立处理并跟读，后续提问不能重复收123；不以逗号代替音频停顿。
- **计数与跟读条件分开。** 纯编号念得快仍收集，但不满足低速等条件就不自动跟读。混合表达工具成功不等于证明WPM达标，不伪造编号片段时间。
- **保护不阻塞普通请求。** 混合表达/更正不能被“编号未满位继续等”无限拦住；工具失败保留原有效状态与错误记录，按现有失败链路反馈。
- **成本与延迟。** 混合表达需要对话LLM及工具往返，通常比本地纯编号路径慢；不增加纯编号调用，不把本次文档确认解释为真实付费测试授权。

## 4．必须纳入后续自测

| 输入或事件 | 预期 |
|---|---|
| 纯123、两位12、独立单单元 | 整体格式通过才走本地；跟读条件不变 |
| 我的号码是123；123，嗯，45 | 整句走混合路径；工具前不追加、不本地跟读 |
| 不是123，是124；把第4位改成3 | 清空工具成功后要求完整重念；不收123124或43 |
| 不是123 → 不是123，是124分包到达 | 不把ASR包各自当完整输入；更正数字不先入库 |
| 同范围纯编号Partial后来修订成混合句 | 重新分流、旧任务失效；已处理范围不被工具重复追加 |
| 提交/清空工具重复、超时、非法或迟到 | 不重复计数、不误清新代次、不口头伪报成功 |
| 已独立处理123后再问位数 | 保留此前事实并正常回答，不重复收集 |

以上是测试契约，不是已通过结果。原型同步、核心实现、真实厂商兼容与工具调用质量仍待验证。行为真源见[voice-pipeline Delta](../specs/voice-pipeline/spec.md)，决策依据见D-040～D-042。

已提交Partial的当前同范围首个有效Final一律停止旧回答、更新上下文并以Final重答，不做含义比较。相同文字、格式变化、意思变化均测试。重复Final及旧轮次Final不重答；取消后的旧token/音频不得进入新回答；已成功工具不得重复执行；已播事实不能撤回。D-049替代D-043中的实质改义条件。
